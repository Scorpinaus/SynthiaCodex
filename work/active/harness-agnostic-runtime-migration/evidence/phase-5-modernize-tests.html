Implementation record

What changed

Discovery

Removed the dynamic behavior runner

Each feature test class now owns its fact methods and display names. A failure points to the method that contains its setup and assertions.

Fixture

Added a one-purpose executable

The Unicode fixture reads one UTF-8 line and writes it back. It has no product or test framework dependency.

Boundaries

Added test traits and collections

Focused commands can select each category. Two non-parallel collections protect native and WPF ownership.

Time

Injected TimeProvider

CoalescingSettingsStore and AppServerNotificationBatcher accept a clock. Production uses the system clock. Tests advance a manual clock.

Messages

Added retained probes

The probe stores messages before or after a waiter starts. Persistence and navigation tests now wait for the exact state transition.

Projects

Added a pure test assembly

SynthiaCode.Tests.Unit runs without a Windows target or a WPF dependency. Tests that need App, Infrastructure, native state, or WPF remain in the Windows assembly.

Legacy

Split mixed test ownership

The three boundary-specific classes contain their own fact bodies and collection policy. LegacyRuntimeTestSupport contains only shared helpers and test doubles.

Signals

Removed state polling

StateProbe listens to property, collection, command, and test signals. Transport request waits use a retained MessageProbe. Command tests await the command task when it is the exact completion boundary.

Guard

Expanded Phase 5 architecture tests

Tests reject polling helper names and delayed polling loops. They also pin the non-Windows unit project, pure-test removal from the Windows build, legacy owner counts, and non-mixed collection ownership.

Mistakes and corrections

The no-build baseline used stale output

It showed an old Phase 3 metadata assertion and one polling timeout.

Correction: a full build became the source baseline. The stale assertion was updated, and the timeout path moved to a message probe.

The first restore could not authenticate NuGet TLS

The build stopped before compilation.

Correction: repeated the same restore with approved network access. The Release build then passed with no warnings.

The first fact conversion still used registry indexes

xUnit discovery was correct, but the test source still had a large wrapper and old delegate lists.

Correction: removed the wrapper and every registry. The original feature methods became the facts.

The first WPF category run found two ordering assumptions

One test read navigation before its collection update. Another depended on the old runner synchronization context.

Correction: waited for exact save and collection messages. Direct fact execution then passed.

The project-graph test treated the fixture as production

The fixture appeared as an unexpected production project.

Correction: classified the fixture as test support and added a separate Phase 5 fixture boundary test.

Four focused commands built into one folder at the same time

The WPF command could not copy the test assembly because another command still used it.

Correction: completed the shared build first and ran the remaining WPF command with --no-build. xUnit parallelism stays inside one test process.

The first completion review was too shallow

The suite was green, but one mixed legacy owner, 175 polling calls, and the Windows-only test project still broke the approved boundaries.

Correction: audited source ownership and wait patterns, reopened Phase 5, and added architecture rules that make the omitted work visible.

The first generated boundary classes were empty

A PowerShell line object was converted as an object instead of as its text value.

Correction: read the original registry as plain strings, rebuilt the three direct-fact classes, and ran all legacy cases before the next edit.

The first signal conversion exposed six weak waits

Some predicates watched plain lists or local variables that did not publish a change event. One model test also completed before its default reasoning value was ready.

Correction: used retained transport and coordinator messages, awaited exact command tasks, and strengthened the model-ready predicate.

The first Release WPF repeat found a reconnect race

The general state probe did not receive the required health transition in one broad run. Awaiting the full model command then waited for unrelated follow-on protocol work.

Correction: interrupted the stalled focused run and used an explicit property-message probe for the exact reconnect boundary. The repeated WPF gate and full Release gate passed.

What this phase taught us

Lessons

Discovery

One fact must equal one behavior

Direct fact methods give stable names, direct source navigation, and useful filters.

Timing

A timeout is not a state signal

A manual clock controls when time moves. A message probe controls when state is ready.

Parallelism

Parallelism needs ownership rules

Pure tests can share CPU. Native and WPF tests must own their process and dispatcher state.

Builds

Parallel tests are not parallel build commands

One build must produce the assembly. Focused test commands can then reuse it with --no-build.

Fixtures

A process fixture must have one job

A separate executable makes the tested process boundary visible and keeps the test assembly conventional.

Migration

Move behavior bodies with their owners

One-line wrappers can prove discovery, but maintainable test boundaries need the setup and assertions in the boundary class.

Projects

A trait is not a compile boundary

A pure category inside a Windows project still compiles against Windows. A separate project makes the dependency rule real.

Signals

Wait for the smallest true completion boundary

Use the event or command that proves the assertion. Do not await a larger workflow that can start unrelated work.

Guards

An audit result must become a rule

The architecture suite now rejects the same polling and ownership patterns that made the first completion claim incomplete.
