Task presentation

A small shell and five feature boundaries

Named controls, keyboard handlers, drag-and-drop handlers, and scroll state moved with the feature that uses them. This prevents the shell from knowing the internal names of the conversation and composer controls.

ShellTaskView

Delegates focus and composes the page.

TranscriptConversation

Turns, find, copy, edit, fork, and scroll.

InputComposer

Prompt, queue, attachments, skills, and dictation.

Side stateAgents and goals

Own their collections, commands, and edit state.

Run setupOptions

Owns model, reasoning, Fast mode, and flyout state.

Compatibility rule

TaskViewModel remains the application-facing facade. It forwards established properties and commands to the feature models. New task XAML binds to TaskWorkspace.Conversation, Composer, Agents, Goals, or Options. This lets application code migrate without one large breaking change.

Pure text boundary

Parse first, apply policy next, render last

InputMarkdown text

No UI or file access.

Pure codeParser and model

Blocks, inlines, tables, links, images, and HTML shapes.

App policyURI and image policy

Accepts or rejects destinations.

WPFMarkdownTextBlock

Creates inlines, grids, images, and actions.

MarkdownTextBlock.cs fell from 2,089 lines to 894 lines. Syntax changes can now be tested without a WPF dispatcher. Link and image safety did not move into the parser.

Implementation record

What changed

Solution

Added a pure presentation library

SynthiaCode.Presentation was added to the solution and referenced by App and Tests. The architecture graph now enforces its zero-dependency rule.

Task XAML

Moved XAML and handlers together

Conversation scroll and find code moved to the conversation control. Attachment, composer, skill, and input code moved to the composer control. Options keyboard code moved to the options control.

Task state

Created five feature models

Agents, goals, and options own their state and commands. Conversation and composer provide focused binding surfaces over the task facade while the compatibility migration continues.

Markdown

Removed the parser from the WPF control

The WPF control consumes a parsed document. It still owns safe destination decisions and WPF object creation.

Git

Changed the view to use component paths

GitView.xaml now binds through repository selection, changes, and actions. Push guards call the push-planning component.

Tests

Updated namescope-aware tests

WPF tests now find named elements inside feature controls. Source checks read the correct feature XAML file instead of the old monolithic shell.

Honest migration log

Mistakes and corrections

The first table parser split a pipe inside a code span

A cell such as `left|right` became two cells.

Correction: the table tokenizer now protects code spans and escaped pipes. A focused Phase 4 test keeps this rule.

The first inline merge removed the wrong equal text node

Value-based list removal could remove an earlier space node that had the same value. This changed output order.

Correction: the parser now replaces the item at its exact index. The complete 307-case behavior set then passed.

The first conversation XAML extraction omitted its outer Grid

The extracted row definitions became direct children of a UserControl. The XAML compiler rejected the file.

Correction: added the feature Grid and rebuilt App with zero warnings and zero errors.

The first behavior run still searched the old root namescope

Fourteen presentation checks could not find controls that had correctly moved into child namescopes.

Correction: changed source checks to read feature XAML and added a shared namescope-aware WPF test lookup.

The first lookup helper called the visual API for a row definition

RowDefinition is a dependency object but is not a visual. The helper threw during six tests.

Correction: removed the unnecessary visual scan. Logical-tree and namescope lookup are sufficient and faster.

One persistence test timed out during the first broad run

The failure happened before the presentation baseline corrections. It did not recur in the next behavior runs or the final full suite.

Correction: treated it as an observation, reran the complete behavior set, and required a clean full Release suite before completion.

What this phase taught us

Lessons

Namescopes

A WPF split changes test lookup rules

A named child belongs to its feature control. Tests must follow namescopes instead of assuming that all names belong to the page shell.

Ownership

Move behavior with the named controls

Scroll, keyboard, focus, and drag handlers are easier to maintain when they live beside the XAML elements that they control.

Parsing

Pure extraction can reveal old implicit rules

Table code spans and equal text nodes were easy to miss during a mechanical move. Characterization tests must run before cleanup continues.

Safety

Syntax is not destination policy

The parser can describe a link or image without deciding whether the application can open it. This keeps security decisions at the host boundary.

Migration

A compatibility facade reduces refactor risk

Views can use focused components now while application callers move later. The facade must stay explicit so it does not become a hidden permanent dependency.
