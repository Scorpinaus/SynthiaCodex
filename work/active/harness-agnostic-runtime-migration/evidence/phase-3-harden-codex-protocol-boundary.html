Implementation record

What changed

Connection

Outgoing state moved out

The request dictionary, numeric ID allocation, response completion, cancellation registration, read loop, write gate, failure-once guard, and owned transport moved to JsonRpcConnection.

Incoming state

Approval state stayed with the facade

Incoming request and responding-request sets remain separate from outgoing requests. This preserves exact-once approval responses and resolved-request invalidation.

Feature JSON

High-change request shapes moved to codecs

Initialization, thread start, turn start and steer, review start, turn interrupt, skill list/write, and account reads use grouped encode/decode classes.

Composition

Production uses the facade

The session coordinator stores CodexClient instances, associates approval IDs with the correct client generation, and disposes the facade during replacement.

Compatibility

Existing features remain stable

The old public name derives from CodexClient. No Core request model, app-server method name, reconnect rule, notification batching rule, or Codex-only side feature changed.

Honest migration log

Mistakes and corrections

The first facade patch missed an expression-body token

The notification helper lost its =>. The first Infrastructure build failed with three syntax errors.

Correction: restored the token, inspected the changed block, and rebuilt with zero warnings and zero errors.

The first thread codec copied the wrong active-profile shape

The draft decoder used a three-value constructor that does not exist and looked at the wrong JSON property.

Correction: copied the established activePermissionProfile behavior exactly, including string and object forms.

A compact switch reused one pattern variable name

The first turn-input validator used image for two adjacent patterns. The compiler rejected the shared scope.

Correction: used distinct localImage and dataImage names, then rebuilt the codec.

The first protocol test used fragile raw-string braces

Interpolated JSON test strings did not have enough delimiter markers for nested closing braces.

Correction: constructed response fixtures with JsonObject. This also made request IDs explicit.

A source-file move left two copies

The guarded patch created the destination but could not remove the tracked source. That briefly produced two CodexClient declarations.

Correction: removed the incomplete destination, kept the verified source path, and confirmed that only one facade type remained.

An obsolete marker made the clean suite noisy

The first compatibility type produced warnings in the existing characterization tests.

Correction: kept the compatibility type without the marker. Production use is still enforced by the new coordinator dependency and the Phase 3 structure test.

What carries forward

Lessons for later phases

Transport state and domain state are different

Outgoing request correlation belongs to JSON-RPC. Incoming approval lifetime belongs to the typed Codex facade.

Compile after each extraction

Small builds found syntax, constructor, and pattern-scope errors before they could mix with behavior failures.

Use builders for JSON test fixtures

Structured fixtures make nested objects and dynamic IDs clear. They also remove raw-string delimiter mistakes.

Compatibility can be quiet and explicit

A small derived type keeps source compatibility. The production composition root and structure tests still identify the supported facade.

Do not combine protocol and product changes

This phase changed ownership and names. It did not change method semantics, Core models, reconnect policy, or Codex-only goals, reviews, and skills behavior.

Phase boundary

What Phase 3 leaves stable

Core protocol records, the app-server coordinator interfaces, reconnect behavior, approval decisions, notification batching, and the Phase 2 durable format did not change. Goals, reviews, and skills remain Codex-specific side features. Review and skill JSON moved behind feature codecs, but their product behavior did not move to the portable conversation facade.

Stable handoff

New protocol work can start in one feature codec or one parser. Connection changes can be tested without changing typed Codex behavior. Application code has one supported client name.
