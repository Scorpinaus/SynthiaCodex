Implementation

What changed

Application ownership

A cohesive Conversations feature folder

The controller and four use-case services moved physically and by namespace into SynthiaCode.Application.Conversations. Application builds independently without WPF or App references.

Facade

Internal services are hidden from composition consumers

ConversationFeatureFacade constructs lifecycle, execution, persistence, and queue services, forwards workspace events, and owns queue disposal. AppServices exposes the facade rather than each service.

State ownership

Conversation reduction is serialized

The workspace gates runtime indexes and reducer snapshots together. A completion is recorded as terminal so a delayed turn/start continuation cannot mark that turn running again.

Queue integrity

Dispatch preparation is data, not a callback

The caller prepares a FollowUpDispatchPreparation once. Application verifies that its follow-up ID is still at the queue head before beginning a durable dispatch transaction, rejecting stale work before provider contact.

Presentation

Events replace timing-sensitive UI hooks

Pending, failed, and started transitions carry detached snapshots and operation origin. The UI clears direct-turn attachments on the accepted pending transition without clearing queue, review, or prompt-edit drafts.

Scope discipline

Codex-only surfaces stayed separate

CodeReviewUseCaseService now consumes IConversationWorkspace but remains in App. Goals and skills were not pulled into the portable facade merely because they share a screen.

Honest migration log

Mistakes and corrections

The first move stopped at compile errors

TaskViewModel lacked the new namespace import, and ten tests still constructed the old queue/service shapes.

Correction: treated compiler failures as a dependency inventory, rewired production first, then updated characterization fixtures without weakening assertions.

An architecture assertion used the wrong xUnit shape

The first reflection test used Assert.Single(collection.Where(...)), which triggered analyzer xUnit2031 under warnings-as-errors.

Correction: used the predicate overload so the architecture guard remains warning-free.

Attachment cleanup was attached to the wrong event

Clearing attachments only after the remote turn-start response delayed UI acknowledgment behind automatic rename and broke the captured-context characterization.

Correction: clear only direct-turn attachments on the accepted pending transition; operation origin prevents queue, review, and edit drafts from being erased.

Re-reading the latest snapshot did not fully solve fast completion

A response and completion can resume on different continuations. The first fix reconciled returned state in MainViewModel, but a narrow window still allowed start registration after completion and concurrent snapshot enumeration.

Correction: serialized reducer access in IConversationWorkspace and made terminal turn state monotonic. The rapid follow-up case then passed repeatedly and in the full suite.

The architecture document had its phase label pinned by a release test

The first full gate passed 375 tests and failed one metadata assertion because the document correctly said Phase 1 while the test still expected the old Phase 21 label.

Correction: rebaselined the metadata contract to the explicit Architecture migration Phase 1 heading.

What carries forward

Lessons for later slices

A state owner must own serialization too

Collecting methods behind an interface is insufficient if response continuations and provider events can reduce the same mutable state concurrently.

Events describe accepted transitions

Presentation should react to an accepted pending/start/completion event, then reconcile long-running returned results with the current workspace rather than assuming the result is newest.

Identity belongs beside prepared work

Queue preparation without the follow-up ID is vulnerable to head changes. Carrying identity lets Application reject stale work before external effects.

Move one vertical slice, not every adjacent feature

Keeping goals, reviews, and skills as explicit side features reduced scope while still proving the facade and workspace pattern end to end.

Phase boundary

What Phase 1 deliberately did not absorb

Provider-specific goals, dedicated review semantics, skills, account state, permissions, and effective configuration remain outside the portable conversation facade. The next phase can extract or redesign another complete slice while using this phase's facade, state-owner, event, and terminal-ordering rules as the reference.

Stable handoff

The architecture boundary is now executable: one facade enters the conversation feature, one workspace owns its mutable runtime state, and callback-free requests keep presentation behavior out of Application transactions.
